# Довідник yaml

`yaml` читає й пише де-факто конфігураційний формат YAML. Потребує Go 1.24+
і не має сторонніх залежностей.

English version: **[DOC.md](DOC.md)**.

## Призначення

Пакет відповідає на одне питання - **«що каже цей конфігураційний файл?»** -
для файлів, які сервіс читає на старті: налаштування, маніфести, куровані
каталоги, фікстури для тестів.

Це навмисно не повна реалізація YAML 1.2. Повний YAML - велика мова з
закутками, якими майже не користуються конфігураційні файли і щодо яких
різні читачі не згодні між собою. Цей пакет покриває ту частину, з якої
файли справді складаються, а решту відхиляє поіменно - тож ввід або
розбирається так, як він виглядає, або падає з номером рядка.

## Коли брати

- Читання конфігурації, маніфестів і фікстур у Go-структури.
- Запис їх назад - згенеровані каталоги, експорт налаштувань, - коли вивід
  має бути стабільним байт-у-байт.
- Скрізь, де ввід може прийти від користувача: декодер обмежений і за
  глибиною, і за розгортанням аліасів.

## Коли не брати

- Потрібні кілька документів в одному потоці, директиви `%TAG`, власні
  прикладні теги або нескалярні ключі мап.
- Потрібне саме виведення типів за YAML 1.1 (див. *Скаляри*).
- Потрібно зберігати коментарі й форматування при циклі
  «прочитати - змінити - записати». Пакет декодує у значення, а не в
  дерево документа.

## API

```go
func Unmarshal(data []byte, v any, opts ...Option) error
func UnmarshalFile(filename string, v any, opts ...Option) error
func UnmarshalReader(r io.Reader, v any, opts ...Option) error
func UnmarshalString(s string, v any, opts ...Option) error

func Marshal(v any, opts ...Option) ([]byte, error)
func MarshalFile(filename string, v any, opts ...Option) error
func MarshalWriter(w io.Writer, v any, opts ...Option) error
func MarshalString(v any, opts ...Option) (string, error)

type Option func(*settings)

type Unmarshaler interface{ UnmarshalYAML(decode func(any) error) error }
type Marshaler   interface{ MarshalYAML() (any, error) }

type SyntaxError struct{ Line int; Msg string }
type TypeError   struct{ Line int; Msg string }
```

Чотири форми кожного напрямку різняться лише тим, звідки беруться байти
або куди йдуть. Решта виражається через опції, типи Go і теги полів, як в
`encoding/json`.

### Unmarshal

`v` має бути ненульовим вказівником. Порожній документ (порожньо або лише
коментарі) лишає його недоторканим і повертає nil.

Декодування в інтерфейс дає:

| YAML | Go |
|---|---|
| мапа | `map[string]any` |
| послідовність | `[]any` |
| рядок | `string` |
| ціле | `int64` |
| дробове | `float64` |
| булеве | `bool` |
| null | `nil` |

Ключі мап - рядки, як у JSON, тож розібраний документ безпосередньо
порівнюється з тим, що прийшов через `encoding/json`.

### Marshal

Колекції пишуться відступними блоками, по два пробіли на рівень (якщо
`WithIndent` не каже інакше); порожня
мапа чи послідовність пишеться як `{}` або `[]`. Ключі мап сортуються -
числові за значенням, решта лексично, - тож одне й те саме значення завжди
дає ті самі байти. Поля структур зберігають порядок оголошення.

Рядки беруться в лапки щоразу, коли без лапок вони прочиталися б як щось
інше: число, булеве значення, маркер документа або значення, яке інший
читач розрізав би на два рядки. Саме через останнє U+0085, U+2028 і
U+2029 пишуться як `\N`, `\L` і `\P`: читач, який їх шанує, побачив би
один скаляр як два.

Рядок із невалідним UTF-8 - це помилка: escape-послідовності YAML
називають символи, а не байти, тож такому значенню просто нема запису.

## Опції

Опція задає типовий вибір на рівні виклику, який тег поля може
перекрити. Пріоритет: **тег поля, потім опція, потім вбудований вибір**.

| Опція | Що робить |
|---|---|
| `WithStrict()` | невідомий ключ є помилкою |
| `WithRequiredAll()` | кожне листове поле обов'язкове |
| `WithExpand()` | розкриває `${NAME}` і `$NAME` із середовища |
| `WithExpandStrict()` | те саме, але невизначене ім'я є помилкою |
| `WithTimeLayout(layout)` | типовий формат для `time.Time` (типово RFC3339) |
| `WithFileMode(mode)` | права, з якими `MarshalFile` створює файл (типово 0o644) |
| `WithIndent(n)` | пробілів на рівень вкладеності (типово 2) |
| `WithParser[T](fn)` | як прочитати `T` з тексту |
| `WithEncoder[T](fn)` | як записати `T` текстом |

### WithStrict

`Unmarshal` ігнорує ключі, яких ціль не знає, - це правильно для
документа, що його мають читати кілька версій програми. `WithStrict`
робить із такого ключа помилку, і це правильно для файлу, який людина
веде руками: там невідомий ключ майже завжди є одруківкою у відомому, а
пропустити його означає, що написане автором налаштування просто ніколи
не спрацює.

Це ловить і документ, написаний за конвенціями іншої мови. `//` є
законним текстом звичайного скаляра YAML, тож файл у стилі
закоментованого JSON розбирається чисто й означає не те, що задумано:

```yaml
{
  // service name
  "name": "app",
  "port": 8080
}
```

Цей документ валідний. Його перший ключ - рядок
`// service name "name"`, тож звичайне декодування заповнить `port` і
лишить `name` порожнім без жодного слова. `WithStrict` повідомить про це
з номером рядка.

### WithTimeLayout

Приймає формат за еталонним часом Go або ім'я константи стандартної
бібліотеки: `RFC3339`, `RFC3339Nano`, `RFC1123`, `RFC1123Z`, `RFC822`,
`RFC822Z`, `RFC850`, `ANSIC`, `UnixDate`, `Kitchen`, `Stamp`,
`DateTime`, `DateOnly`, `TimeOnly`.

### WithParser і WithEncoder

Вхід для типу, який не може реалізувати текстові інтерфейси, - зазвичай
тому, що він не ваш. Зареєстроване перетворення перемагає все, що пакет
робив би з цим типом інакше (бо інакше воно не було б входом), і діє на
сам тип, на вказівники на нього та на елементи зрізів і масивів із нього.

```go
err := yaml.Unmarshal(data, &cfg, yaml.WithParser(func(s string) (Money, error) {
    return ParseMoney(s)
}))

out, err := yaml.Marshal(cfg, yaml.WithEncoder(func(m Money) (string, error) {
    return m.String(), nil
}))
```

## Відповідність структурам

```go
type Source struct {
    Slug    string   `yaml:"slug"`
    Quality int      `yaml:"quality"`
    Tags    []string `yaml:"tags,omitempty"`
    Secret  string   `yaml:"-"`
    Note    string   // ключ "note"
}
```

- `yaml:"name"` задає ключ.
- `,omitempty` пропускає поле, коли воно нульове, порожній рядок, зріз,
  мапа чи масив, або нульовий вказівник чи інтерфейс.
- `yaml:"-"` пропускає поле в обидва боки.
- Поле без тегу відгукується на **нижній регістр** свого імені, бо ключі
  YAML за угодою пишуть з малої.
- Вбудована (embedded) структура без тегу віддає свої поля напряму, як в
  `encoding/json`. `,inline` на вбудованій структурі просить те саме й
  приймається; на іменованому полі - відхиляється, бо «кошик решти
  ключів» не реалізований, а тихе ігнорування втратило б усі ключі, які
  мали туди потрапити.
- Поле, яке структура оголошує сама, перемагає однойменне, здобуте через
  вбудовану структуру, хоч би яке з них було написане першим.
- `,required` відхиляє документ, який не задає цей ключ.
- Будь-яка інша опція тега відхиляється, а не ігнорується.
- Пошук ключа спершу точний, потім без урахування регістру.
- Ключі, яких структура не знає, ігноруються - крім випадку, коли
  документ читали з `WithStrict`.

Разом із полем ідуть ще два теги:

| Тег | Значення |
|---|---|
| `def:"..."` | значення, яке взяти, коли ключа немає |
| `layout:"..."` | формат для поля `time.Time` |

### Присутність, значення за замовчуванням і required

Ці три речі узгоджуються в одному порядку, і його варто назвати, бо
відповіді випливають саме з нього:

1. розкриваються merge-ключі (`<<`);
2. присутність визначається на об'єднаній мапі;
3. відсутній ключ бере своє `def`;
4. `required`-ключ, якого й далі немає, дає помилку.

Присутність визначається **після** merge, тож ключ, який дав merge,
рахується присутнім: декодер, строгий режим і `required` працюють з
однією й тією ж мапою, і тільки так вони можуть узгоджено відповісти, що
означає «ключ є».

Явний `null` **не є** відсутністю:

```yaml
port: null      # з def:"8080" -> 0, замовчування не діє
                # з ,required  -> задоволено, ключ на місці
```

Написати `null` - це дія. Замовчування, яке її скасовує, скасовувало б
рішення людини, що писала файл, а `required` питає, чи автор звернувся до
налаштування, а не чи значення непорожнє.

Поле не може мати одночасно `,required` і `def`: воно мусило б і бути в
документі, і мати значення на випадок, коли його немає. Ця суперечність
повідомляється при першому використанні структури, а не залагоджується
тихцем.

`WithRequiredAll` вимагає кожен **листок**. Вкладена структура
заповнюється власними ключами, тож сама по собі не обов'язкова, і
необов'язкова секція, якої немає, лишається відсутньою; листки присутньої
секції мають бути на місці.

## Типи

Окрім базових видів, `[]byte`, вкладених структур, мап, вказівників,
зрізів і масивів:

| Тип | Читається з | Пишеться як |
|---|---|---|
| `time.Duration` | `"30s"`, `"1h30m"` | `30s` |
| `time.Time` | тексту у форматі поля | текстом у тому форматі |
| `url.URL` | тексту, через `url.Parse` | текстом URL |

Тривалість читається з **рядка**. Голе число відхиляється:

```
yaml: line 4: a duration must be written as a string like "30s"
(a bare number would mean nanoseconds)
```

Прочитати `timeout: 30` як тридцять наносекунд було б правильно й
непотрібно. Таймаут, у мільярд разів коротший за задуманий, не падає там,
де хтось пов'яже це з конфігураційним файлом.

`url.URL` розбирається, а не валідується. Відносне посилання на кшталт
`/callback` є URL і лишається ним; пакет не вимагає схеми й хоста, бо в
тих, хто його викликає, законно буває ввід без них.

Часові мітки не резолвляться неявно: `at: 2026-09-01` під core-схемою є
рядком і стає `time.Time` лише тому, що так каже поле. Поле типу `any`
отримає рядок, тож документ, розібраний у структуру, і той самий
документ, розібраний у `any`, ніколи не розходяться в тому, чим є
значення.

## Власне декодування типу

Тип, що реалізує `Unmarshaler`, отримує свій вузол і сам вирішує, що з
нього зробити:

```go
func (l *Level) UnmarshalYAML(decode func(any) error) error {
    var s string
    if err := decode(&s); err == nil {
        return l.parseName(s)
    }
    var n int
    if err := decode(&n); err != nil {
        return err
    }
    return l.parseNumber(n)
}
```

`decode` можна викликати не один раз, і кожен виклик розбирає **той
самий** вузол наново - саме так пишеться тип, який приймає або рядок, або
число. Кожен виклик рахується в обмеження декодера, тож тип не може
вийти за них циклом.

Сам вузол не передається. Тому тип не бачить, чи його скаляр був у
лапках, аліасом чи з явним тегом. Це навмисно: інакше форма внутрішнього
дерева цього пакета опинилася б у публічному API, де її вже ніколи не
змінити.

`Marshaler` - зворотний напрям, повертає значення, яке треба записати
замість себе:

```go
func (l Level) MarshalYAML() (any, error) { return l.String(), nil }
```

`MarshalYAML`, що повертає власного одержувача, - це цикл. Він дає
помилку, а не роботу до вичерпання стека.

Пріоритет в обох напрямках: зареєстрований парсер або енкодер, далі ці
інтерфейси, далі типи з таблиці вище, далі
`encoding.TextUnmarshaler` / `encoding.TextMarshaler`, далі базові види.

## Розкриття змінних

`WithExpand` замінює `${NAME}` і `$NAME` у значеннях скалярів на
відповідну змінну середовища. Типово вимкнено.

```yaml
host: ${DB_HOST}
url:  https://$DB_HOST/api
```

**Лише значення, ніколи ключі.** Ключ, що залежить від середовища, робить
документ нечитним і ламає перевірку на дублікати.

**Лише звичайні та подвійно-лапковані скаляри.** Одинарні лапки й блокові
скаляри - це літеральні форми YAML, і вони лишаються літеральними; саме
так пишеться значення, яке мусить зберегти свій `$`:

```yaml
literal: '${AMOUNT}'
script: |
  echo ${AMOUNT}
```

**Ім'я має читатися як ім'я**: літера або підкреслення, далі літери,
цифри чи підкреслення. Усе інше зберігає свій `$`. Саме тому виживають
ціна, шелов-однорядковик і пароль:

```yaml
price:    "cost: $100"   # без змін
awk:      "$1 == x"      # без змін
password: pa$$word       # без змін, подвоєний $ ніколи не є посиланням
```

Власного екранування для `$` немає, і це свідомо: другий шар екранування
поверх YAML-івського був би головоломкою. Відповідь - літеральні форми
вище.

**Усередині flow-колекції braced-форму треба брати в лапки.** Це YAML, а
не властивість пакета: `{` і `}` є індикаторами flow, тож звичайний
скаляр там не може містити `${...}` взагалі.

```yaml
urls: [https://${HOST}/a]     # помилка: expected ',' or ']'
urls: ["https://${HOST}/a"]   # добре
urls: [https://$HOST/a]       # добре
```

**Підстановка відбувається після того, як парсер зафіксував межі скаляра,
і до того, як визначено його тип.** Важливі обидві половини. Змінна, що
містить двокрапку чи перенос рядка, змінює одне значення й ніколи -
форму документа, тож конфігураційний файл не можна перебудувати через
середовище. І `port: ${PORT}` усе одно приходить числом, бо текст
резолвиться після підстановки; це також означає, що при декодуванні в
`any` вийде те, що написано в підставленому тексті.

**Невизначене ім'я розкривається в ніщо**, і це тихо: ключ присутній, тож
поле з `,required` задовольняється значенням, якого немає.

```yaml
database_url: ${DATABASE_URL}   # не задано -> "", і required задоволено
```

`WithExpandStrict` натомість відхиляє це, називаючи змінну й рядок. Він
сам вмикає розкриття.

`Marshal` ніколи не згортає значення назад у `${NAME}`. Обіг через
`WithExpand` асиметричний за задумом.

Значення з `def` розкривається на тих самих умовах, що й значення з
файлу.

Тип, що реалізує `encoding.TextUnmarshaler`, отримує текст скаляра як
написано, **до** будь-якої резолюції за схемою - тож ваш власний тип сам
вирішує, що означає `2026-08-30`. Той самий тип із
`encoding.TextMarshaler` записується тим текстом, який він видає.

## Скаляри

Прості (без лапок) скаляри резолвляться за core-схемою YAML 1.2. Скаляри в
лапках і блокові - завжди рядки.

| Запис | Стає |
|---|---|
| порожньо, `~`, `null`, `Null`, `NULL` | null |
| `true`, `True`, `TRUE`, `false`, `False`, `FALSE` | bool |
| `42`, `-17`, `+5` | ціле |
| `0x1F`, `0o644` | ціле |
| `3.14`, `.5`, `1e3`, `.inf`, `-.inf`, `.nan` | дробове |
| будь-що інше | рядок |

Два наслідки варто сказати прямо, бо саме тут читачі YAML найчастіше не
згодні між собою.

**`yes`, `no`, `on`, `off` - це рядки.** У core-схемі рівно два булевих
значення. Поле типу `bool` усе одно приймає ці написання, як і явний
`!!bool`, бо там ціль сама заявляє намір; поле типу `any` отримає рядок.

**Ведучий нуль відхиляється.** `0644` - це вісімкове за YAML 1.1 і
десяткове за 1.2. Обидва прочитання захищаються, і вони різні, тож парсер
відмовляється обирати за вас:

```
yaml: line 1: "0644" is ambiguous: a leading zero meant octal in YAML 1.1
and decimal in 1.2; write 0o644 for octal, 644 for decimal, or quote it
for a string
```

Пишіть `0o644`, `644` або `"0644"`. `0`, `00` і `0x1F` це не зачіпає - вони
однакові за будь-якого прочитання.

Підкреслення в числах (`1_000`) не входить у core-схему й дає рядок.
Часові мітки - теж рядки; якщо їх треба розбирати, дайте полю власний тип
із методом `UnmarshalText`.

Null не може бути ключем мапи. `~: 1` відхиляється, бо при декодуванні
дав би порожній ключ, зіткнувся б там зі справжнім `"": 1`, і одне зі
значень зникло б без жодного слова. У лапках `"~"` - звичайний текст і
працює.

### Теги

`!!str`, `!!int`, `!!float`, `!!bool` і `!!null` нав'язують прочитання, і
значення, яке тегу не відповідає, дає помилку, а не тихий відкат.
`!!float` приймає цілий запис; `!!bool` приймає слова з YAML 1.1.

## Структура документа

Підтримується: блокові мапи й послідовності за відступами; flow-колекції
`[a, b]` і `{k: v}`, які можуть займати кілька рядків; одна пара
`ключ: значення` як елемент послідовності (`[2, indent: 1]` означає
`[2, {indent: 1}]`); коментарі; опційні `---` на початку і `...` в кінці.

Відступи - пробіли. Табуляція у відступі - помилка, бо табуляція не є
коректним відступом YAML, а вважати її таким - це саме те, через що два
редактори починають по-різному бачити один файл. Після індикатора
табуляція - звичайний роздільник, тож `ключ:<таб>значення` і
`-<таб>елемент` читаються як належить.

### Блокові скаляри

`|` зберігає розриви рядків, `>` згортає їх у пробіли. Обидва приймають
індикатори chomping: `-` (прибрати кінцевий розрив) і `+` (зберегти всі
кінцеві розриви), а також явну цифру відступу.

Усередині folded-скаляра рядок із більшим відступом зберігає власну
розкладку: розриви навколо нього не згортаються. Порожній рядок додає
власний розрив.

## Анкори, аліаси та merge-ключі

`&name` позначає значення, `*name` його повторює:

```yaml
defaults: &defaults
  retries: 3
  timeout: 30

fast:
  <<: *defaults
  timeout: 5      # fast.retries = 3, fast.timeout = 5
```

Ключ `<<` вливає мапу - або послідовність мап - у ту мапу, що його
містить. Ключ, який мапа заявляє сама, завжди перемагає влитий, а
попередній елемент послідовності злиття перемагає наступний: злиття
заповнює прогалини й ніколи не перезаписує.

Аліас може називати лише вже завершений анкор. Це робить циклічне
посилання **непредставним**, замість того щоб декодер мусив його виявляти.

## Обмеження

Декодер має лишатися безпечним на вводі, написаному щоб його зламати.

| Обмеження | Значення | Що зупиняє |
|---|---|---|
| глибина вкладення | 512 | документ, що рекурсує до кінця стека |
| операцій декодування | 1 000 000 | аліаси, що розгортають малий документ у величезний граф |
| напрям аліаса | лише назад | циклічні посилання |
| кодування | лише UTF-8 | байти, щодо яких жоден читач не дійде згоди |

Перевищення обмеження - звичайна помилка, не паніка.

## Помилки

Кожна помилка називає рядок:

```
yaml: line 2: unterminated flow sequence
yaml: line 7: mapping key "slug" already defined at line 4
yaml: line 3: tab characters are not allowed in indentation
yaml: line 5: cannot decode string into int
```

Номер рядка доступний і без читання повідомлення - заради цього й
існують два типи помилок. Зіпсований документ дає `*SyntaxError`;
документ, який сам по собі коректний, але не лягає в ціль, дає
`*TypeError`:

```go
var se *yaml.SyntaxError
if errors.As(err, &se) {
    editor.Highlight(se.Line)
}
```

Дубльовані ключі мапи - помилка, а не «перемагає останній»: у
конфігураційному файлі повторений ключ є помилкою, і саме її мовчазний
варіант коштує дорого.

`*TypeError` може водночас бути однією із sentinel-помилок пакета, тож
`errors.Is` і `errors.As` обидві дають відповідь, і не треба обирати між
тим, що сталося, і тим, де це сталося:

```go
var (
    ErrNilObject     // Unmarshal чи Marshal отримав nil
    ErrNotPointer    // Unmarshal потребує ненульового вказівника
    ErrNotStruct     // потрібна була структура
    ErrInvalidObject // значення неможливо закодувати
    ErrRequired      // обов'язковий ключ не задано
)

if errors.Is(err, yaml.ErrRequired) { ... }
```

Імена збігаються з тими, що вживає `.env`-половина цього набору, тож одна
й та сама перевірка читається однаково, з якого б формату програма не
завантажувала конфігурацію.

## Що не підтримується

Відхиляється зі змістовною помилкою, а не реалізовано наполовину:

- кілька документів в одному вводі;
- директиви `%YAML` і `%TAG`;
- власні та прикладні теги, зокрема `!!binary`;
- складені (нескалярні) ключі мап, зокрема форма `?`;
- збереження коментарів і форматування.
